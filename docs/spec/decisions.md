# Design decisions and open items

## Decisions

| A2  | Hepburn-only mode is deferred (D9)                                                                                                                                                                                                                                       | Implement as a filter in the MVP                                                              | Conflicts with strict IME mode (を is `o` in Hepburn, `wo` in IME)                                                                                                                                                                                                                                                             |

| A5  | Sign-out clears data on the device after a sync attempt and a confirmation if data is unsent                                                                                                                                                                             | Keep it as guest data                                                                         | Protects data on shared computers                                                                                                                                                                                                                                                                                              |

| A11 | Prompts are matched as one stream across boundaries (D3)                                                                                                                                                                                                                 | Per-prompt matching with a 250 ms absorption window                                           | Absorption swallows the first `n` of a following prompt and produces false errors in a stream                                                                                                                                                                                                                                  |
| A12 | Superseded by A36. A group unlocks when all its kana reach box 1; only due reviews promote higher                                                                                                                                                                        | Unlock at box 2                                                                               | Unlock at box 2 delays every group by at least one day (12–26 days per script)                                                                                                                                                                                                                                                 |

| A15 | In relaxed mode a single n completes ん at a prompt boundary before any next spelling (ほん → あめ = honame); strict mode requires nn before a vowel, as in IME                                                                                                          | Require nn at a boundary in both modes, as inside a prompt (D2)                               | The visible gap between prompts reads as a word boundary, and typing honname there causes avoidable errors; relaxed remains a superset of strict, so the invariant holds                                                                                                                                                       |
| A16 | Content reports are protected by Cloudflare Turnstile                                                                                                                                                                                                                    | WAF rate limiting; per-IP limits in D1                                                        | WAF rules need an own DNS zone, which \*.pages.dev is not; D1 counters spend the write budget                                                                                                                                                                                                                                  |
| A17 | A new deviceId is generated on every sign-in from guest mode (renewing an expired session keeps it, A27)                                                                                                                                                                 | Store a batch id next to seq on the server and reject mismatches                              | Removes the seq-reset case with no extra server state                                                                                                                                                                                                                                                                          |
| A18 | Words are built from the original JMdict XML                                                                                                                                                                                                                             | jmdict-simplified JSON                                                                        | jmdict-simplified keeps only a common flag; the fallback selection needs the priority tags and nfXX ranks                                                                                                                                                                                                                      |
| A19 | Tatoeba phrases are credited per sentence (source link on the training screen, full list on `/about`)                                                                                                                                                                    | Use only the CC0 subset of Tatoeba, which needs no credit                                     | The Tatoeba terms require the author of each CC BY sentence to be cited; the CC0 subset is much smaller and may not yield 300–500 verified phrases                                                                                                                                                                             |
| A20 | JLPT levels come from Jonathan Waller's lists via the pinned stephenmk/yomitan-jlpt-vocab mapping                                                                                                                                                                        | OpenJLPT dataset; JMdict priority tags only                                                   | The mapping provides JMdict entry ids directly under a licence compatible with JMdict; identical OpenJLPT copies exist under several owners, so its provenance is less clear; priority tags do not reflect JLPT levels                                                                                                         |
| A21 | A time or count test ends after 5 s without input; it is saved and counted as finished but gives no personal best; zen is exempt                                                                                                                                         | Wait for the timer; allow a personal best                                                     | An abandoned test should not distort the history, and without the exclusion a 5-second burst inside a 60-second test could set that mode's record. Zen is defined by having no limits                                                                                                                                          |
| A22 | Statistics are applied only when a test is saved; a restart discards them (D23)                                                                                                                                                                                          | Record per prompt, as in the baseline                                                         | A restart means the user rejects the attempt; it also keeps the IndexedDB write in one transaction with the result                                                                                                                                                                                                             |
| A23 | A hidden tab ends a running test at once                                                                                                                                                                                                                                 | Keep the 5-second idle rule while hidden                                                      | The browser may discard a hidden page, which would lose the test; a hidden tab cannot receive input anyway                                                                                                                                                                                                                     |
| A24 | Superseded by A43. Personal bests for content `kana` are kept per set of selected rows                                                                                                                                                                                   | Only for preset row sets; one record per mode                                                 | One record per mode lets a vowels-only test set the record for all kana; presets would give no record for a custom set                                                                                                                                                                                                         |
| A25 | Amended by A43: the store is `records` and also keeps the last 10 results per key. A dedicated `bests` store, merged by maximum on acknowledgement                                                                                                                       | Recompute from `results`; add to `delta`                                                      | Results can be evicted and a guest has no snapshot; a maximum converges with the server, which applies the same rule                                                                                                                                                                                                           |
| A26 | `user_stats` is written with optimistic concurrency on a `version` column                                                                                                                                                                                                | Rely on the 5-second sync interval                                                            | `batch()` makes the write atomic but does not protect the preceding read, so concurrent syncs would lose increments, and the interval check is itself subject to the same race                                                                                                                                                 |
| A27 | A `401` keeps local data; re-signing as the same user resumes under the same deviceId; signing in as another user never merges                                                                                                                                           | Treat a `401` as sign-out; merge everything                                                   | Sessions expire after 30 days, so a `401` is routine and must not lose data; merging would put one person's data into another's account                                                                                                                                                                                        |

| A29 | History is local-first, filled from the server on demand; a signed-in device keeps 1,000 results                                                                                                                                                                         | Server-only history; download everything at sign-in                                           | Works offline and spends D1 reads only when older history is opened                                                                                                                                                                                                                                                            |
| A30 | Amended by A35: lessons are now learning sessions. Reviews are recall only; a lesson is not resumable; due dates fall on local calendar days                                                                                                                             | Mixed review formats; persist lesson state; rolling 24-hour intervals                         | Recall is the trained skill; a lesson is short, so saved state is not worth a new synced record; a rolling interval would hide a kana from a daily review done slightly earlier                                                                                                                                                |
| A31 | From P2 the MVP interface follows the Nekotype design system, with views separated from logic (ADR 031)                                                                                                                                                                  | Keep a basic MVP interface and redesign it in v1.1                                            | The design system already exists and the screens are written in P2–P5 anyway, so a later redesign would do the work twice; separated views still keep visual changes away from behaviour and its tests                                                                                                                         |
| A32 | Generated content is imported as Vite chunks, carries no Russian glosses, and a contributor's sentence with は or へ that differs from kuromoji is excluded                                                                                                              | Static files with a fetched manifest; ship `ru`; keep such sentences without hints            | Vite provides hashing and prefetch with no new code; `ru` is not displayed in the MVP; a sentence without hints would reject the natural `wa` in relaxed mode                                                                                                                                                                  |
| A33 | "Reset progress" is available to guests only; signed-in users do not see it until a server-side reset exists                                                                                                                                                             | Reset the device only; design a server reset for the MVP                                      | Sync only adds deltas, so a local reset would be undone by the next snapshot; deleting the account already lets a signed-in user start over                                                                                                                                                                                    |
| A34 | An error is never charged to a prompt before the one on display: a wrong key or a hint after `hon` in ほん → ねこ is charged to ね                                                                                                                                       | The plain minimum over active positions, which charges the undecided ん                       | The user finished the previous word correctly and is looking at the new one; the plain minimum would make every word-final ん collect mistakes that belong to the next kana                                                                                                                                                    |
| A35 | Learning kana is the core of the MVP and typing words and phrases its second part: speed tests on single kana are removed, a saved `content: 'single'` becomes `words`, `/` is the learning screen and typing moves to `/type` ([ADR 058](../adr/058-learning-first.md)) | Keep single-kana speed tests as a second mode, and `/` for typing                             | Typing romaji as the measure of knowing a kana rewards spelling it letter by letter ("n-a" instead of "na"); romaji stays the way to answer and a real skill for words. Words are the closest content left, and the main screen shows the main part of the product                                                             |
| A36 | Kana unlock one at a time in track order when every unlocked kana of the track is confident; a kana waits until the kana it is built from are confident                                                                                                                  | A group unlocks when all its kana reach box 1 (A12)                                           | Confidence measures speed and accuracy, where two correct answers did not; one new kana at a time keeps a beginner's set small, as in keybr. Boxes still schedule retention but no longer gate progress                                                                                                                        |
| A37 | The recall answer time is `max(t_first, t_last − (n − 1) × K)`, where K is the median of the device's last 50 typing intervals (200 ms while fewer than 20 are recorded); K is not synced                                                                                | The time to the first accepted key; the time to the last key; one K for all devices of a user | The first key shows only that the consonant was recognised (き and け both start with `k`), and the last key includes typing speed, so し (`shi`) would always be slower than あ (`a`). Subtracting the user's own interval leaves the time to recall the whole kana. Typing speed depends on the keyboard, so K is per device |
| A38 | Confidence counts recall answers only; recognition records accuracy and mixups                                                                                                                                                                                           | Count recognition answers too                                                                 | Choosing from four options is easier than recalling, and its time is not comparable with a recall time                                                                                                                                                                                                                         |
| A39 | Typing and learning statistics are separate: a typing test writes per-kana attempts and errors to `KanaStat`, which only weight words; learning neither reads nor writes `KanaStat`, and the migrated baseline statistics stay typing data                               | Feed typing errors and times into learning; one shared per-kana record                        | Typing speed depends on touch typing, so it would distort confidence. Attempts and errors keep `weakFocus` working; wrong-key counts, confusions and reaction times have no screen left                                                                                                                                        |
| A40 | While some kana have fewer than 10 recall answers, half of the tasks go to them; the rest are chosen by weight `1 + 4 × min(1, slow + err)`                                                                                                                              | A fixed large weight for a new kana; weights alone                                            | A fixed share gives a new kana its 10 answers within one or two sessions, however large the unlocked set; a fixed weight would count for less as the set grows                                                                                                                                                                 |
| A41 | The streak is stored as runs of active local days; the current and best streaks are derived from them                                                                                                                                                                    | Store the current and best streaks as numbers                                                 | Numbers cannot be merged: two devices active on consecutive days would each hold a short streak. A union of runs merges exactly and stays small                                                                                                                                                                                |
| A42 | The daily median answer time comes from per-day buckets of 100 ms                                                                                                                                                                                                        | A daily mean; a daily median kept per device                                                  | A median needs the distribution; buckets add up across devices, and 100 ms is finer than the chart shows                                                                                                                                                                                                                       |
| A43 | Typing records keep, per key, the personal best and the last 10 results counted in the average, in a synced `records` store; the key has no row set                                                                                                                      | Personal best only; an average from the local `results` store                                 | Typing speed often depends on touch typing, so a record alone discourages and an average shows progress. The average must be the same on every device, and the history of a new device is empty until fetched. Without single-kana content the row set leaves the key                                                          |
| A44 | Kana sounds are recorded files with an open licence, played through an `AudioProvider`; speech synthesis is not the main path                                                                                                                                            | Browser speech synthesis                                                                      | Synthesised voices differ by platform, and some platforms have no Japanese voice; a recording sounds the same everywhere                                                                                                                                                                                                       |

## Resolved items

Checked against primary sources on Nov 1, 2026.

- **O1 — Tatoeba licence.** All Tatoeba exports, including transcriptions, are released under CC BY 2.0 FR; part of the sentences is also available under CC0 1.0. Reuse requires citing the author of each sentence and distributing it with its licence. Resolved by per-phrase credit (A19).
- **O2 — JLPT list.** Jonathan Waller's lists (CC BY) through the stephenmk/yomitan-jlpt-vocab mapping (CC BY-SA 4.0) (A20). The JMdict priority-tag selection remains only as a fallback.
- **O4 — Cloudflare free tier.** Confirmed: 100,000 requests per day and 10 ms CPU per request; Pages Functions share the daily quota with Workers, and static asset requests are free and unlimited; D1 allows 5 million rows read and 100,000 rows written per day, and an index write counts as an additional written row; after a limit is exceeded, D1 queries fail until midnight UTC; 500 MB per database, 5 GB per account, at most 2 MB per row. The 2 MB row limit applies to `user_stats`, which holds all statistics of a user as JSON. Limits are rechecked before P5 (backend and sync), since they can change.
- **O5 — "Reset progress" action.** A maintainer decision, not a source check. Resolved by A33.

## Open items

- **O3.** Define the Russian gloss coverage threshold for enabling Russian translations in v1.1, based on the P4 coverage report.
- **O6.** Choose the source of the kana recordings for P6 (A44). It needs a licence that allows redistribution, one speaker and recording level for every learnable kana of both scripts, and an attribution that fits `/about`. Candidates to evaluate: recordings on Wikimedia Commons, or recordings made for the project and released under CC0.
- **O7.** Decide whether a signed-in user can reset learning. Design system v10 proposes (design decision 91) a "Reset learning" action in the Data section of `/settings` for signed-in users: it erases learning progress on every device and keeps typing statistics, needs the server, and is disabled offline, with an expired session or with sync blocked. Today "Reset progress" is for guests only (A33). Decide before P5.
- **O8.** Decide whether `・` and the fullwidth digits `０`–`９` stay in the Noto Sans JP subset. They were added for the Japanese mode label of the typing results (`ことば・３０`), which design system v10 removed (design decision 85); the current words and phrases contain none of them. Decide with the content pipeline in P4, once its glyph set is known.
