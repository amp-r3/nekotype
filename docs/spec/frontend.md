# Frontend

Two pages take keyboard input: learning on `/` ([Learning](learning.md)) and typing on `/type`, a Japanese text stream with a romaji buffer at the caret. A keystroke MUST NOT trigger a component render on either.

## Input source (D14, D15)

1. Input is captured by a hidden `<input>` with `autocomplete=off`, `autocorrect=off`, `autocapitalize=off`, `spellcheck=false`.
2. A `keydown` listener on `document` keeps the baseline behaviour: when focus is outside the hidden input (for example on the Restart button after Tab), outside any text field and no dialog is open, a typable key returns focus to the hidden input and is processed as input. Modifier combinations and keys inside dialogs are not intercepted. Ctrl/Cmd+Enter is intercepted only while it would end a test (a running zen test); otherwise it is left to the browser, so on a link it opens the link and the focus stays where it is.
3. A `keydown` carrying a single latin character, `-` or `'` is handled immediately and cancelled with `preventDefault`. This is the primary desktop path. A repeated `keydown` (`event.repeat`, a held key) is cancelled and is not input: it is not a keystroke, is not counted and does not reset the idle timer. A typed character that is not input (a digit, a space, a mark) is left to the browser and, on `/type`, only resets the idle timer, as do the non-Latin letters and kana of items 6 and 7 (metrics.md, "Idle end").
4. A `keydown` with `key` = `Unidentified` or `Process` (mobile keyboards) is skipped; characters arrive via `beforeinput` (`insertText`, `data` field), one intent per character.
5. When `beforeinput` is not cancelable (Gboard composition), an `input` fallback compares `value` with the last value seen and processes only the added characters. The field is not cleared during composition; it is cleared on `compositionend`. Character duplication on Gboard is a known risk and is part of the P2 device-matrix check.
6. A non-latin letter is rejected without counting as an error; a "switch your keyboard layout to English" notice appears and hides after the next latin character.
7. The "turn off the Japanese IME: Nekotype converts romaji itself" notice is shown only when composition data contains kana or kanji. Composition events with latin data (Gboard on Android) do not show it. Latin text of a composition is held back until the IME is shown to be off: a consonant waits (with the IME on it is only the placeholder of a kana), a latin vowel releases it (an IME that is on would have made kana of it) and so does a composition that ends without kana, or a key typed directly. Kana drop whatever is held, so a Japanese IME that is on never starts a test or counts a mistake with its first letter. A latin vowel in a composition also hides the notice; a consonant does not. The only cost on Gboard is that the first consonant of a word is processed together with the vowel after it.
8. The `handleIntent({kind:'char', char})` seam for an on-screen keyboard is retained.
9. The hidden field belongs to the page, not to the screen inside it. On `/type` it stays in the document on the results screen. Restart, the zen "Finish" button and "Next test" give it the focus synchronously inside their click handler, because a phone keeps its keyboard open only for a focus set during the gesture. The field takes keys on the test screen only; on the results screen a key is left to the controls there (ADR 055).
10. On `/` the field takes keys in introduction and recall tasks; in a recognition task the keys 1–4 choose an option, and on the chart and the summary a key is left to the controls there. "Continue" and "Review" focus the field in their click handler, and it keeps the focus through a session, so a phone keeps its keyboard open between tasks.

## Text stream and romaji buffer (D13)

- **Stream:** on `/type`, 2–3 lines of prompts; the current line is in focus and completed lines scroll up. Prompts are separated by a gap. The engine window is extended as described in [Input engine rules](engine.md); it holds the prompts the stream draws after the displayed one, between 44 and 72 tokens (ADR 040, 043). The text that leaves the stream leaves in whole lines: the stream starts at the first prompt of the line above the caret, so no remaining token changes its line or its place on the screen when the stream is redrawn, and the caret does not move across the screen (a measurement puts it in place at once, with no transition). Only a view with no layout falls back to a cap in tokens (ADR 047). A prompt that fits a line is never broken; a prompt wider than the whole line (a long phrase on a phone) breaks inside, only between tokens, and never splits a yōon, `っ` from the next kana, a kana from its `ー` or the punctuation after it, or an opening bracket from the next kana. Which prompts are that wide is decided when the stream is measured, never on a keystroke (ADR 060).
- **Token states:** upcoming (`untyped`), completed (`fur`), current (`eye` caret before the token), errored (`miss` with a `miss-dim` underline). Skip tokens are rendered; the caret passes over them.
- **Romaji buffer** next to the caret renders the remainder from `engine.view()` as latin; displayed tokens are already marked in the stream. It does not shift the text. Example for きて: `k` → buffer "k"; `ki` → き is marked and the buffer is empty; `kit` → buffer "t".
- **Translation** of the current word or phrase is shown below the stream, in English in both locales (the content has no Russian); its height is reserved for two lines, since a translation wraps on a narrow screen and the stream must not move (the design's rule); controlled by `showTranslation` in settings, on by default. A phrase also carries a **Source** link (`source` / `источник`) to `https://tatoeba.org/sentences/{id}`, opened in a new tab with `rel="noopener"`: it is the sentence's attribution, so it stays when the translation is off, sits in the reserved line and does not take the focus from the hidden input. "Report a problem" is added in P5.
- **Live indicators:** the counter (time left or prompts completed), KPM and kana accuracy, on one line above the stream.
- **Repeat mark:** during a repeat ([Metrics](metrics.md)) the same line shows "repeat" in `fur-dim` with a `stroke-hair` outline. It is rendered once per test and does not change on a keystroke.
- **While a test runs,** the navigation and the config bar are hidden and leave the tab order, so the first Tab reaches Restart. They fade out and then leave the tab order; a mouse movement of more than 8 px shows them until the next key (ADR 041). Tab and Shift do not hide them again, so the keyboard can reach the navigation; any other key does, and every key press forgets where the mouse movement started, so a slow drift over a whole test shows nothing (ADR 055). The translation line with its actions, the hint, notices and the zen "Finish" button stay available. Space for them is reserved, so the text does not move.

Keys in hints and documentation are written as in the design system (ADR 059): `+` joins keys pressed together (`ctrl + enter`), `→` joins keys pressed in turn (`tab → enter`).

## Hot path (D16)

- Signals are passed into JSX as text nodes or written to the DOM via `useSignalEffect` and refs. Token state classes are toggled via `classList` on refs, without re-rendering.
- Keystrokes are tracked with counters; the keystroke array is no longer copied.
- A keystroke that does not complete a prompt: **0** component renders. A keystroke that completes a prompt: at most **1** render (the stream line component). Verified by a test using `options.diffed`, following `render-isolation.test.tsx`.
- A recall task keeps the same budget: **0** renders for a keystroke that does not finish the answer, at most **1** for the one that does. The next task, shown after the pause, renders once.
- A task of a learning session is drawn by the design system's `KanaTask`, not by the stream view. Its controller, `createTaskController`, is the task's DOM writer: `setBuffer` (recall), `type` (introduction), `reject`, `finish`, `reset` (hidden tab), `setWindowFocus` and `setInputFocus`. It changes classes, text and transforms only, with positions measured on layout, not on a keystroke (ADR 059).
- Animations use `transform` and `opacity` only; `prefers-reduced-motion` disables them, as in the baseline.
- A rejected key flashes the caret in `miss` for 120 ms through a separate layer animated with `opacity`. With `prefers-reduced-motion` the colour changes for 120 ms without a transition.
- Noto Sans JP is loaded with `<link rel="preload">` (absent in the baseline).

## Loading

After the first render, on `requestIdleCallback`, the client prefetches all lazy route chunks and the content chunks matching the current typing settings. This keeps the application usable when the network drops after load.

Vocabulary (words, phrases) is loaded per chunk: the selected content and script name the chunks (`hiragana` or `katakana` load that script's chunk, `both` loads all chunks of the kind, [Content pipeline](content.md)), and only the selected ones matter to the typing screen:

- While the selected vocabulary loads, the stream is empty (it keeps its height), typing is ignored and a loading notice is shown. A chunk that arrives is cached; it restarts the test only if it belongs to the selection.
- A failed load never changes the content setting. The notice names the failure and offers Retry; until it succeeds there is nothing to type, since there is no fallback kana pool ([ADR 058](../adr/058-learning-first.md)). A failure of a chunk that is not selected shows nothing.
- A selected vocabulary that has loaded but holds nothing for the selected script (phrases written only in katakana: the pinned sources give none, [ADR 070](../adr/070-phrase-selection.md)) is not an error: the stream stays empty, typing is ignored and the slot says so and names `Both` as the way out. The setting is not changed.
- Loading, error and "nothing for this script" notices share one reserved slot above the stream, so none moves the text. The slot hides with the other interface while a test runs.
- The phrase `source` link opens Tatoeba in a new tab, so the page becomes hidden and a running test ends by the hidden-tab rule ([Metrics](metrics.md), "Test end"); it is saved or discarded under the same conditions.
- The results screen, the session summary, the Russian dictionary and the strings that only one lazy screen uses (a dictionary part per screen and language, loaded with the screen) are chunks of their own, fetched on idle with the others ([ADR 057](../adr/057-lazy-results-screen-and-russian-dictionary.md), [ADR 067](../adr/067-initial-chunk-before-p4.md)). A screen is not shown before its strings: a part that fails to load fails the screen, with Retry. If a test or a session ends before its chunk is there, a loading notice stands in its place (an error with Retry on a failure), and Next test, Continue and Enter work meanwhile.
- A saved Russian language holds the first render until its dictionary has loaded; if it cannot be loaded the interface is in English and the choice stays saved. The language switch loads the dictionary first (with the parts of the screens opened so far) and changes the language only then.
- Leaving the typing screen drops a running test without saving it (metrics.md, "Test end"). Leaving a learning session keeps its recorded answers ([Learning](learning.md)).

## UI architecture

From P2 the interface follows the [Nekotype design system](../design/README.md) (A31, [ADR 031](../adr/031-adopt-the-nekotype-design-system.md)); no separate redesign is planned. Views stay separated from logic, so a later visual change does not touch behaviour.

- **Logic stays out of components.** Components in `ui/` read `ReadonlySignal` state and call exported actions. They MUST NOT call the engine, `Clock`, `Scheduler`, storage or `fetch`, and hold only local presentation state such as an open dialog. Everything else lives in `model/` and `lib/`.
- **One exception for the hot path:** DOM writes through refs and `useSignalEffect` stay in hooks in the slice's `lib/`, with a small interface the view binds to, so a new view reuses them and keeps the render budget.
- **Tests target behaviour.** Logic is tested at the `model/` and `lib/` level without rendering. e2e and DOM tests select by role, label or `data-testid`, never by class name or DOM structure. The DOM carries no answers for tests: a test works out the expected input from what the page shows (ADR 045). Replacing a view MUST NOT require changing a model test.
- **Styling** uses only the CSS-variable tokens and `shared/ui` primitives; a page defines no colours or one-off components of its own.

**Slices** (a starting point; ADR 015 still merges a slice with a single consumer into it):

| Layer      | Slices                                                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages`    | `learn` (`/`; also the learning session and task choice), `trainer` (`/type`), `stats`, `settings`, `about`                                                                        |
| `features` | `training` (`createSession`, the typing session), `sync`, `report-content`                                                                                                         |
| `entities` | `prompt` (picker, weights, content), `stats` (typing statistics, local view, results, records), `learn` (learning state, confidence, unlocking, boxes, streak), `user`, `settings` |

Slices on one layer do not import each other, so a flow crossing features, such as sign-out running a sync first, is composed in the page or in `app`. The input source, used by both sessions, is in `shared` ([Architecture](architecture.md)).

Typing options stay in the config bar on `/type`: content (words or phrases), script, strictness, test kind and length, weak kana; there is no row selection. Below 640 px the bar is folded into one line naming the mode (`words · hiragana · relaxed · 30 s`), a button that opens the full bar under it. Typing and learning each have their own strictness (`typing.strictness`, `learn.strictness`, [Storage and sync](storage-sync.md)): the config bar labels its group "Strictness", `/settings` labels the other "Learning strictness". The navigation holds the logo, links to `/` (learn), `/type`, `/stats` and `/settings`, the `en`/`ru` switch and a sign-in link to `/settings`, hidden on previews; `/about` is linked from the page footer. During a learning session the navigation and the footer are not rendered; the session line holds "Leave session" instead ([Learning](learning.md)). "Reset progress" is on `/settings`, for guests only (A33). The report dialog has a `reason` select, an optional comment and the Turnstile widget.

## Interface

- All strings, including `aria-label` values and chart titles, come from the i18n dictionaries. Exception: kana row names are the romaji labels from the kana table, identical in every language ([ADR 044](../adr/044-row-names-are-romaji.md)).
- The layout is responsive: every feature works on a phone; the primary layout target is desktop.
- One dark theme; colours remain CSS-variable tokens so that themes can be added without structural changes.
