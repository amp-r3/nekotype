# Implementation phases

The MVP is delivered in eight sequential phases. At the end of every phase `verify` passes and production on `nekotype.pages.dev` is deployable. P3–P7 were reordered on Nov 6, 2026, when learning became the core of the product ([ADR 058](../adr/058-learning-first.md)).

1. **P0 — Monorepo and hygiene.**
   - pnpm workspaces; the baseline `src/` moves to `apps/web`; the engine and kana tables move to `packages/engine` with the table passed via `createEngine`; guards and the `Clock`/`Scheduler`/`Rng` types move to `packages/shared`.
   - Fix the D20 defects, bring documentation and CI in line with D21, update the budget script.
   - **Acceptance:** all baseline tests pass (106 unit, 8 e2e); behaviour is unchanged except for the D20 fixes, each covered by a new test; `packages/engine` has no imports; deployment to the Pages project `nekotype` succeeds and production is served at `nekotype.pages.dev`.
2. **P1 — Engine.**
   - Stream matching with prompt boundaries, `extend()`, rules D2–D8 and D22, attribution D10, flag D11, `compact()`, `view()` with the display-position rule, `errorTarget()`, `committedPrompts()`, `committedTimings()`, `spellingsFor()`, `canonicalFor()`, recording of "expected kana → typed character" pairs, removal of `shouldAbsorb`.
   - **Acceptance:** every input of the accepted-input and rejected-input tables is a golden test; boundary tests cover ん → n, ん → vowel, ん → skip token, っ at a boundary; `packages/engine` coverage ≥ 95%; property tests pass, including the invariant that relaxed accepts every input strict accepts; compact() keeps indices valid over a 1,000-prompt zen stream; all baseline words and phrases compile.
3. **P2 — Input and training screen.**
   - Design-system foundation (tokens, fonts, logo, favicon; ADR 031, ADR 032), hybrid input source, layout and IME notices, text stream, romaji buffer, render-free hot path, `createSession`, keyboard table, zen finish, idle prefetch, font preload, all strings moved to i18n, dependency-free router with route stubs and `_redirects` entries, the slice layout and view separation from "UI architecture".
   - **Acceptance:** session and input logic is tested without rendering; render test shows 0 renders per keystroke and ≤ 1 on prompt completion; keystroke work p95 ≤ 8 ms and keystroke → next frame p95 ≤ 2 frames; e2e (b) from the baseline passes (typing with focus on a button); IME notice not shown for latin composition; device-matrix pass for input on Android (Gboard) and iOS (deferred to the P7 device-matrix pass when P2 was closed, 2026-11-06).
4. **P3 — Learning.**
   - IndexedDB: the database `nekotype` with the stores P3 uses (`settings`, `delta`, `meta`), and the reset on a changed `SCHEMA_VERSION` ([ADR 061](../adr/061-schema-reset-before-release.md)); later phases add their stores by raising `SCHEMA_VERSION`. Nothing is migrated: `kanaflow:settings:v1` is deleted at the first start, and `showTranslation` becomes a required field. The typing screen reads and writes its settings in IndexedDB; `kanaflow:progress:v1` stays in localStorage, read by the typing screen as in P2, until P4.
   - Learning on `/` ([Learning](learning.md)): tracks, unlocking with dependencies, learning sessions (introduction, recall, recognition with the distractor rules and the visually-similar table, focus and weighted task choice), the answer time with K, confidence, boxes and review sessions, the session summary, the kana chart with its states, the mastered count and the streak, learning settings, `learn` counters, the learning section of `/stats`. "Reset progress" also clears the learning state.
   - Typing moves to `/type` as a lazy route and keeps its P2 behaviour otherwise. The `/learn` stub and its route are removed, with no redirect. Content `single`, the row selection and the fallback kana pool are removed; the latency test runs Words and Phrases.
   - The input source moves to `shared`. `AudioProvider` is injected into the learning session with a provider that plays nothing, called after every task.
   - Design system version 10 ([ADR 059](../adr/059-design-system-v10.md)): `KanaTask` with `createTaskController` for learning tasks; `shared/ui` takes the design's names (`Toggle` → `Switch` with the label and description on the left, button variant `ghost` → `text`), drops the line under `Nav` and under the `Dialog` title, writes `en / ru` in lower case, and the loading notice no longer blinks; key hints use `+` and `→`; "Show the romaji" on touch screens, in recall and on `/type`; the config bar folded on a phone; a prompt wider than a line breaks between tokens ([ADR 060](../adr/060-long-prompt-breaks-between-tokens.md)).
   - Fonts: the glyphs listed under "Glyphs to add to subsets" in the [design decisions](../design/source/decisions.md) are added to the subsets ([ADR 034](../adr/034-design-tokens-and-font-build.md)): `·` in JetBrains Mono 400; `⌘` in JetBrains Mono 400; `−` (U+2212) in JetBrains Mono 400 and 500 and Golos Text 400; U+00A0 and U+202F in Golos Text and JetBrains Mono, 400 and 500. Each font stays within its budget.
   - **Acceptance:**
     - property tests with a seeded `Rng`, a fake `Clock` and a simulated learner whose answers come from a seeded model, on both tracks: kana unlock one at a time and only when every unlocked kana is confident; no kana unlocks before its dependencies are confident (ヴ unlocks before ヴァ and ヴィ); the unlocked set never shrinks; っ, ー, small kana, ゐ and ゑ never appear; answers in one track never change the other; the same seed gives the same sessions;
     - task choice with a fixed `Rng` over 10,000 draws: a kana is chosen no less often when its median answer time or its error count grows; kana in focus get 50% ± 2% of the tasks while kana out of focus exist; recognition gets 1/3 ± 2% of the tasks; the same kana never comes twice in a row when another is available;
     - answer time on fixed keystroke times: with K = 200 ms, あ typed at 800 ms and し typed at 800, 1000 and 1200 ms both give 800 ms, and き typed at 300 and 1100 ms gives 900 ms; the result never falls below the time of the first accepted key; K changes from 200 ms to the median of the last 50 intervals at the 20th interval; intervals across a rejected key or Esc are left out; an answer's own intervals do not change its time;
     - confidence at its boundaries: with the default target a median of 1500 ms is confident and 1501 ms is not; 9 correct answers of 10 are confident and 8 are not; 9 answers are never confident; a changed target applies at once;
     - boxes with a fake `Clock` in a fixed time zone: the first confidence moves a kana to box 1, due the next local day; promotion and demotion by reviews; learning-session answers never change the box of a kana in box 1 or higher; due dates across a daylight-saving change;
     - streak: one answer makes a day active, while an introduction or a typing test alone does not; the local midnight boundary; a missed day resets the current streak and keeps the best one;
     - the session summary on fixed answer sequences; every recognition task has 4 options in every state of both tracks, starting with the vowels; no distractor shares a spelling with the answer in either strictness;
     - a learning session leaves the typing statistics unchanged and a typing test leaves the learning state unchanged; a recall keystroke causes 0 renders and the answer at most 1; no IndexedDB write happens inside a keystroke handler;
     - schema reset: a database with another `meta.schemaVersion`, a missing store or an unreadable `meta` is deleted and created again, and the application starts with default settings without an exception; a failing open leaves the application running from memory with the notice and the legacy keys kept; the first start deletes `kanaflow:settings:v1` and leaves `nekotype:locale` and `kanaflow:progress:v1`;
     - e2e: a full learning session by keyboard (typing and keys 1–4) on Chromium and by tap on WebKit, ending on the summary; a test on `/type`; the deploy smoke test sees `/type` answer 200 with the application and `/learn` answer 404;
     - the budgets pass with learning in the initial chunk and typing as a lazy route chunk.
5. **P4 — Words and phrases.**
   - Content: transcription parser written against the pinned export, then the pipeline, N5–N4 words from the pinned JLPT mapping with homonym merging, 300–500 verified phrases with per-sentence author data, build report, Russian coverage report, `/about` page with source licences and the generated phrase credit list, "Source" link on the typing screen.
   - Typing: KPM and kana accuracy, `TestResult`, test-end rules including idle end and a hidden tab, statistics applied with the saved result (D23), `KanaStat` for word weights, deletion of `kanaflow:progress:v1` at the first start (nothing is migrated), client-side decay, counters, the `results` and `records` stores, the results screen with the difference to the average and to the personal best, "Repeat" and the repeat mark, local history and the typing section of `/stats`, personal-best badge.
   - **Acceptance:** build is reproducible from pinned sources; exclusions ≤ 5% per source; an audit of 50 randomly sampled phrases finds at most one reading error; every phrase has a Tatoeba id and author usernames and appears in the credit list; chunks ≤ 40 KB; font within budget; the first start deletes `kanaflow:progress:v1`; metrics verified on fixed event sequences; idle end verified with a fake `Clock` and `Scheduler`: 5 seconds without input ends a time or count test, zen is exempt, `endedAt` is the last keystroke, and the result gives no personal best; a restart leaves statistics unchanged except `started`; personal-best rule and key covered by tests; the average checked with 0, 1, 10 and 12 earlier results of a key, a repeat left out of it; a repeat replays the same prompts, is saved with `repeated` = true and gives no personal best; `delta` stays one record after 1,000 simulated tests; a typing test leaves the learning state unchanged; lazy chunks within budget.
6. **P5 — Backend and sync.**
   - Pages Functions with Hono, `_routes.json`, D1 migrations, Google and GitHub OAuth, sessions, `/api/sync` with `seq` handling, merge rules (the learning state and the typing records included) and optimistic concurrency, Web Lock, guest merge, sign-out flow, expired-session flow, failed-request handling, server history, account section of `/settings`, account deletion, report action with Turnstile, `/api/reports`.
   - **Acceptance:** API tests on a local D1; e2e "offline → online"; statistics stay visible while a batch is unacknowledged; a resent batch creates no duplicates; a delayed old batch is not applied; two-tab and two-device merge tests; two concurrent syncs lose no increments; an expired session resumes under the same `deviceId`, and signing in as another user never merges the previous user's data; a `400` stops retries until `appVersion` changes; a guest with 1,000 results signs in and all results arrive over several batches; sign-out and sign-in to the same account loses no data; one finished test writes at most 6 D1 rows, measured by meta.rows\_written; request CPU within the limit per `wrangler pages deployment tail`; property tests show that the set-like merges (learning entries, unlocked kana, recent answers, active days, typing records) are idempotent, commutative and associative and the additive ones commutative and associative; two devices learning the same track converge on unlocked kana, recent answers, boxes, active days and buckets; a sync that carries only learning progress writes at most 2 D1 rows; a `user_stats` row with a year of simulated learning on both tracks is merged within the CPU limit.
7. **P6 — Audio.**
   - The source of the recordings (O6), the `sound` field of every learnable kana, the recordings, the file-based `AudioProvider`, the `learn.sound` setting, licence and credit on `/about`.
   - **Acceptance:** every learnable kana of both scripts has a sound, and entries with the same pronunciation share a file; a learning session calls the provider after every task, and never while `learn.sound` is off (fake provider); a sound that fails to load never delays the next task; no sound is part of the first load, and each file is at most 10 KB (`check-budget.mjs`); the sound plays after a key press in iOS Safari and Android Chrome (manual check recorded in the PR).
8. **P7 — Polish and release.**
   - Accessibility pass, device-matrix pass (including the input checks deferred from P2 and the kana sound), updated README and ARCHITECTURE, ADR entries, a stored-data description on `/about`, the release switch of the schema rule (below), release tag.
   - **Release switch** ([ADR 061](../adr/061-schema-reset-before-release.md), [Storage and sync](storage-sync.md#schema-changes)): `SCHEMA_VERSION` is set to 1; after the maintainer has opened the released build once, so that the development database is reset for the last time, a second commit sets `PRE_RELEASE` to `false`; the rule in `AGENTS.md` and the "Schema changes" section change to "migrations are mandatory"; a new ADR supersedes ADR 061.
   - **Acceptance:** Lighthouse ≥ 95 (median of 3 runs); manual pass on the device matrix recorded in the PR; keyboard-only pass through every screen, a learning session included; documentation matches the code; the release tag points at the deployed commit; a test fails when the number of IndexedDB migration steps differs from `SCHEMA_VERSION − 1`, and `PRE_RELEASE` is `false`.
