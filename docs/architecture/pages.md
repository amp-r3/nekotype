# Pages and shared UI

Part of the [architecture description](README.md) of the current code.

## The test screen (`pages/trainer`, ADR 041)

- `pages/trainer/ui/test-stage.tsx` is the screen: the stage; the hidden field that takes the keyboard lives one level up in `trainer-page.tsx`, so it stays when the screen changes (`useTestInput` in `features/training/lib/use-test-input.ts` creates and binds the input source and keeps the focus; `useFinishButton` enables Finish; ADR 055), `LiveLine` (counter, kana per minute, kana accuracy), `TextStream`, one line for notices (layout, IME, the revealed romaji), the translation (English in both locales; two lines reserved together with the `source` link of a phrase, which points to `https://tatoeba.org/sentences/<id>` and stays when `showTranslation` is off; a press on the link does not move the focus from the field) and the hints. Every line whose text a keystroke changes is a signal passed as a text node, so the screen renders once.
- `pages/trainer/lib/results-model.ts` shapes the results screen (the KPM comparisons with U+2212 for a minus, the up to five mistyped kana with the `spellingsFor` of the test's strictness); the default time and count tests are `DEFAULT_TIME_TEST` and `DEFAULT_COUNT_TEST` in `entities/settings`.
- `features/training/ui/text-stream.tsx` renders the tokens of `session.stream` and has no child component; `lib/use-stream-binding.ts` gives the elements to the writer (`lib/stream-dom.ts`) and writes the rest to the DOM through signal effects.
- While a test runs `useTestChrome` sets `data-testing` on the document; the stylesheet turns it into `opacity` and `visibility` for everything marked `data-chrome` (navigation, mode panel, footer). Restart has `nk-on-focus`: it shows when focused or hovered, and always on a touch screen. Tab and Shift keep the interface shown. `useEnterForNext` handles Enter on the results screen.
- The page switches to the results on a `finished` computed value, so the start of a test (idle to running) does not render it. The render test counts every component render of the page from the first key: none for a key inside a prompt, the stream for a key that completes one.

## The learning screen (`pages/learn`)

- `pages/learn` is the learning screen: the chart of the selected track (`KanaChart`: blocks side by side with captions, a legend, a details panel per kana — `KanaChartPanel`), `mastered X of N` and the streak on one row with the track switch (the streak is hidden until the first answer; a first-visit line takes its place), `continue` (focused when the screen is ready) and `review (N)`, then one reserved `Notice` line (loading, a failed read with `retry`, or progress that cannot be saved), where N counts the due kana — confident, box 1 or higher, `dueAt` passed (`isDueKana`, ADR 062) — exactly the due marks of the chart.
  - `model/session.ts` is `createLearnSession(deps)` (`Clock`, `Scheduler`, `Rng`, the learning store, `AudioProvider`), a session of 25 tasks, and a review session of at most 20 recalls.
  - The romaji shown to the learner is `displayRomaji` (`lib/romaji`): the table's canonical spelling, except ん and ン, shown as `n`; an introduction takes only the romaji it shows (another spelling is a rejected key), recall takes every spelling of the learning strictness.
  - After a wrong choice the screen draws the hint to go on: `enter` and `next`, or a `next` button under `pointer: coarse`.
  - `lib` holds task choice, distractors, the review queue, the summary and the hook binding the session to the input source.
  - The session runtime and the summary panel are lazy chunks; the summary screen (its actions and the place of the panel) is part of the session runtime chunk, loaded before a session can end (ADR 067).
  - ADR 015 keeps the session in the page, which is its only consumer.
- `shared/ui` holds `KanaTask`, `createTaskController`, `OptionCard` and `KanaChart` as presentational components: data, states and strings come as props, and they import nothing from `entities` or `pages`. The input source (`shared/lib/input`) serves both the trainer and the learning session.

## The statistics screen (`pages/stats`)

- `pages/stats` (a lazy route; ADR 076) shows one section at a time under the `h1`, `learning` or `typing`. It reads the stores and the history, shapes the data in `lib/` (pure functions with tests) and draws it in `ui/`.
  - **Page** (`ui/stats-page.tsx`): a large `Segmented` switches the section. The section is in the URL hash (`lib/section.ts`: `parseSection`, `initialSection`): a valid hash wins, otherwise the section with data opens, learning when both or neither has it. Choosing calls `history.replaceState`; a `hashchange` listener follows a hand-edited hash; the router is not changed. Only the page reads the clock (`defaultClock`); the sections get `today` as a prop. A guest with no data at all sees the `EmptyState` and no switch; a section without data shows `ui/section-empty.tsx`. Loading and the error with `retry` take the section's place, per store. The page reads the whole history once with `readAllResults` (`allResults()` of `entities/stats`, one `getAll` of the index, oldest first), again when `finished.typing` changes (a test saved in another tab), and hands it to both sections; a failed read only costs the test marks (learning) or shows the error with `retry` (typing). For a signed-in user whose session is valid and who is online (`userId`, `sessionExpired`, `navigator.onLine`), the typing section calls `onReachedEnd` when the last page of the history is on show and the local results do not already reach back past the start of the selected period (`periodCovered` in `lib/selection.ts`); the page then calls `loadOlderResults()` and reads the list again when the store gained results, which runs the check again, until a page brings nothing, the server has no more or the request fails. While a request runs `loading history…` stands under the table. A guest, an expired session and being offline ask for nothing.
  - **Learning** (`ui/learning-section.tsx`): `Stat`s for the current and best streak and the mastered kana of both tracks, the activity map, the answer-time chart and the line of started and finished sessions. The track switch of the chart is local state (it does not change `settings.learn.track`) and is drawn only when both tracks have answers; the period `Segmented` is 7 / 30 days or all, 30 by default. `lib/answer-time.ts`: `dayBars` (one bar per day from `quartilesOf` of `entities/learn`, one per Monday-to-Sunday week above 45 days on the axis), `msAxis` (covers the bars and the target answer time, which is a dashed `reference` line). A period without answers shows a notice with `show all time`.
  - **Typing** (`ui/typing-section.tsx`): until the history is read, the loading notice stands in place of the filter row and everything under it. The filters (`ui/filter-row.tsx`: a `Select` of modes, the period, `with repeats`) are component state, opening on the mode of the newest result, 30 days, no repeats. `lib/selection.ts`: `modesOf`, `defaultMode`, `select` (periods are whole local days), `figures`, and `oneMode`, the one predicate for "the selection is of one mode": the KPM figures, the median line and the mixed-modes caption all use it. Under the filters come the `Stat`s, the chart with a switch of its metric (`lib/metrics.ts`: `METRICS`, `metricAxis`; `kpm`, kana accuracy, rejected keys, hints), the history (`ui/history-table.tsx`, 10 rows a page in memory, `Pagination` only above one page, reset on a filter change; `lib/typing-data.ts`) and `All time`: the personal bests of `typingRecords` and the weak kana table, neither depends on the filters or on the history read.
  - **Chart** (`ui/stats-chart.tsx`, legend in `ui/chart-legend.tsx`): one component for both sections. It draws `points` (one mark per test: a ring for a personal best, hollow for a repeat), `line` and `band` (the rolling median of the last 10 tests and its middle half, from the fourth test, with one mode and five tests or more; `rolling`, `quantile` in `lib/trend.ts`) and `ranges` (the day bars), at the container's real width. With one to four tests `fewAxis` puts the marks into five slots with a caption and no line; several modes give marks only and a caption. Axes: `axisOf` in `lib/trend.ts` picks the smallest step of a list for which the snapped domain has at most four intervals, so every axis ends on a tick (`kpmAxis`, `metricAxis`, `msAxis`; `timeAxis` follows the period). Hover picks the nearest mark; ← → `Home` `End` `Esc` walk them; the tooltip lines are built only for the mark under the cursor, and the tooltip is the chart's `aria-describedby`. The line draws in on mount except under `prefers-reduced-motion`.
  - **Activity map** (`ui/activity-map.tsx`): a column per Monday-first week and a button per day up to today. `lib/activity.ts`: `activityDays` joins the recall answers of both tracks, the typing tests by the local day of `endedAt` and the `activeDays` runs; `levelOf` gives the fill step 0–5 at 1 / 10 / 25 / 50 / 100 answers (an active day without recall answers is 1); `weeksFor` gives 12–26 weeks from the first day, 13 at most below 640 px; `gridDays`. A square marks a test day, a border today. One Tab stop with arrows, `Home` / `End`.
  - **Weak kana table** (`ui/kana-heat.tsx`): the geometry of the kana table on `/` with the shared `.nk-chart*` and `.nk-cell` styles, a cell per kana filled `heat-miss-1…5` by `heatStep` (`lib/kana-heat.ts`, over 0, 3, 7, 12 and 20 % of `erroredAttempts / attempts`; no attempts is an outlined cell). Data comes from `typingKanaStats`; cells are not locked and open nothing. One Tab stop with the arrows through `moveInGrid`. The script switch is drawn only when both scripts have a kana with attempts (`typedScripts`).
  - **Styles and shared parts**: `ui/period-switch.tsx` (`PeriodSwitch`) and `ui/track-switch.tsx` (`TrackSwitch`) serve both sections; `ui/layout.ts` holds the width classes `BLOCK` and `NARROW`; `lib/days.ts` holds `DAY_MS`, `HALF_DAY_MS`, `MIN_DAYS_ALL` and `mondayOf`. The screen's styles (`.nk-rc*`, `.nk-am*`, the heat classes) are in the lazy `ui/stats.css`, not in the initial stylesheet. `Stat`, `Cat`, `EmptyState` and `Pagination` are in `shared/ui` and out of its barrel, so they stay in the lazy chunk; `Pagination` takes its labels as props (`/about` uses other ones).
  - **Tests**: `lib/*.test.ts` cover the pure functions; `ui/*.test.tsx` are per widget and per section (`stats-page`, `learning-section`, `learning-section-data`, `typing-section`, `typing-section-selection`, `typing-section-heat`, `stats-chart`, `activity-map`, `kana-heat`).

## The about screen (`pages/about`)

- `pages/about` (a lazy route; P4 PR 13, ADR 066) shows, in the route chunk, the sources and licences (`ui/source-rows.tsx`: four rows, `CC BY` of Waller's lists without a link, A3) and the terms of Nekotype (code, name and cat, fonts), then the phrase authors (`ui/phrase-credits.tsx`).
  - The list is read from `credits.json`, a content chunk of its own: `loadCredits` in `entities/prompt/api/credits-loader.ts` imports it, checks its shape and keeps the result; a failure is forgotten so `retry` fetches again.
  - The component starts the load when it mounts, and only the list's place shows `loading…` or the error with `retry`. The idle prefetch does not fetch this chunk.
  - `lib/paging.ts` sorts by sentence id and slices pages of 25; the whole list is in memory, so a page change is synchronous, the count line (`role="status"`) announces the range and focus stays on the pressed page button. `Pagination` is the one from `/stats` with its own labels.
  - In a container of 480px or less a row is a block (CSS `.nk-credits`, the `td[data-label]` values become the line labels).
  - The kana audio (P6) and stored data (P7) sections are not rendered yet.

## The settings screen (`pages/settings`)

- `pages/settings` (a lazy route) is in sections: `Learning` (the learning strictness as a `Segmented`, the target answer time as a `Select` of nine values from 1000 to 3000 ms in steps of 250), `Typing` (the translation `Switch`) and `Data` (reset progress, with a confirmation `Dialog`); each row has the setting's name and what it does on the left and the control on the right, under the text below 640 px. `Select` is in `shared/ui` and out of its barrel.

## SVG in components

- SVG attributes are written in kebab-case (`stroke-width`, `text-anchor`): Preact core writes JSX names as they are, and the browser ignores a camelCase one. `app/svg-attributes.test.ts` fails on a camelCase attribute.
