# Typing session and trainer (`features/training`)

Part of the [architecture description](README.md) of the current code.

## `createSession()` and `createTrainer()`

- **Session.** `createSession({ nextPrompt, config, onEnd?, clock?, scheduler?, … })` returns a `Session`: the signals a view reads (`currentPrompt`, `stream`, `caret`, `romajiBuffer`, `mistake`, `phase`, `metrics`, `promptResults`, `completedPrompts`, `correctKeystrokes`, `liveKpm`, `liveAccuracy`, …) and the actions `loadPrompt`, `handleIntent`, `finish`, `endHidden`, `reset` (and `endReason` for the results screen). Everything is held by the instance, so two sessions share no state (D17).
- **End of a test.** `config` is read once per `loadPrompt`, and the test runs by that snapshot; `onEnd` receives an `EndedTest` when a test ends and is kept (`complete`, `manual`, `idle` or `hidden`): times, committed and errored tokens (the unfinished prompt included), completed prompts, keystrokes, rejected keystrokes, hints, the committed tokens per kana (T4) and the errors per kana (rejected keys and hints, for the list of mistyped kana).
- **Saving.** The session writes nothing itself; `createTrainer` assembles the `TestResult` from the report and the settings (`id` a UUID v7 from `shared/lib/uuid`, `kpm` and `kanaAccuracy` rounded by the shared helpers, `contentVersion` from `manifest.json`, `appVersion` the Vite define `__APP_VERSION__`), calls `saveTest` and keeps `{ result, average, previousBest, isBest, kanaErrors }` in `lastSaved` (ADR 073).
- **Unfinished tests.** A test that is not played to its end (`manual`, `idle`, `hidden`) is kept with at least one completed prompt and time behind it, otherwise it is discarded. The idle end is one `Scheduler` timer armed at the first keystroke: a keystroke only stores `lastKeyAt`, the timer re-arms for the rest when it fires early, and at `IDLE_END_MS` (5 s) it ends the test at `lastKeyAt`; zen is exempt. The trainer listens to `visibilitychange` and ends a running test with `session.endHidden()` (also at `lastKeyAt`). The results panel states `idle` and `hidden` with a `Notice`. A restart, leaving the screen or an ending with nothing to keep calls `recordDiscardedTest()` when the test had started.
- **Results panel.** The results panel (a lazy chunk, `pages/trainer/ui/results-panel.tsx`) draws only `trainer.lastSaved` (`FinishedTest`: the `SavedTest` plus the errors per kana of the test, kept in memory): the end-reason `Notice`, the mode line, `Stat size="hero"` with KPM and its comparisons, `PersonalBestBadge` and the `content` cat (`Cat mood`) on a personal best, accuracy, time, `WeakKanaList`, Next test and Repeat. Until the save resolves it offers Next test alone.
- **Repeat.** Repeat (ADR 033, T10): the trainer wraps the prompt source and keeps every prompt the running test took; when the test ends it holds the completed ones and the one under way until the next `restart()` or `repeat()`. `repeat()` serves them in order, then fresh prompts, with the settings of the finished test, sets the `repeating` signal and the result's `repeated`; `restart()` always starts an ordinary test. The live line shows the `repeat` mark from `repeating`, which changes only when a test starts.
- **Metrics.** `metrics` keeps only the raw counts (`elapsedMs`, `correct`, `mistakes`, `accuracy`, `promptsCompleted`); WPM, the speed series and the best streak are gone.
- **Trainer.** `createTrainer()` composes one session with the prompt source (pool, weights, `Rng`) and the loading of vocabulary content; the trainer page creates it, calls `start()` (first prompt, following the settings, content loading) and reads its signals.
- **Content loading.** Vocabulary loads are tracked per chunk (ADR 046; `entities/prompt/api/content-loader.ts`): the selected content and script name the chunks to read (`words-hiragana`, …; `both` reads every chunk of the kind), each chunk is fetched once and kept, and while any selected chunk loads the session ignores keys (`inputBlocked`) and no prompt is shown; a failure keeps the setting and offers `retryContent()`; a loaded selection with nothing for the script (`phrases` × `katakana`) is the `noContentForScript` signal: input stays blocked and the notice slot of `trainer-page.tsx` says so; the function returned by `start()` also resets the session, so no timer outlives the screen.
- **Counting.** Keystrokes are counted by `lib/key-tally.ts` (totals plus accepted keys per second), never stored; `lib/metrics.ts` computes `SessionMetrics` from it when a test ends. `liveKpm` and `liveAccuracy` count the tokens before `view().activeToken`, which are committed in every position, once each.

## Windows, line breaking and prompt results

- **Matcher window.** The session keeps the displayed prompt and, after it, up to 72 tokens of prompts in the matcher (`AHEAD_TOKENS`) (`extend` in batches as the caret moves on, no more than a count test needs), so the stream can draw the lines ahead and the context of a non-final ん is known long before it is typed.
- **Stream window.** The stream the view draws is a separate window (ADR 040): `stream` lists the prompts around the caret with their tokens and changes in steps (ADR 043: only when fewer than 44 tokens are left ahead, or when 60 or more tokens can leave the head; what leaves is whole lines, from the first prompt of the line above the caret, which the view reports through `setTrimPoint` (ADR 047); not on every completed prompt); `caret`, `romajiBuffer` and `mistake` change on a keystroke and are meant to be written to the DOM without a render by `lib/stream-dom.ts`. Tokens are numbered from the start of the test, so `compact()` renumbers nothing the view holds.
- **Line breaking.** The view wraps the tokens of a prompt in `nowrap` groups (`lib/token-groups.ts`: a yōon and `っ` with its kana are one token already; `ー` and closing punctuation join the token before, an opening bracket and a lone `っ` the token after), and `lib/stream-dom.ts` marks a prompt wider than the line `is-long` when it measures, so only such a prompt breaks, and only between groups (ADR 060).
- **Touch and narrow screens.** On a touch screen the test screen shows a "show the romaji" button in place of the Esc hint, and below 640 px `ModePanel` folds into a one-line summary with a button that opens it.
- **Prompt results.** The next prompt is shown as soon as `view()` reaches its first token; a prompt's result (`recordPromptResult`, `recordTokenOutcomes`) is recorded when `settledPrompts()` includes it, with `endedAt` the time of the keystroke that committed it; when a zen test is finished by hand or a time test runs out, every prompt before the displayed one is recorded, a final ん included, and `completedPrompts` (the live counter) holds that number (ADR 050).
- **Timings.** `compact()` also lets go of the keystroke times no remaining token needs, and `promptResults` is copied only when read. Token times come from `committedTimings` and the times of accepted keystrokes; the first token of a test has no preceding keystroke and reports `ms` 0, which `updateKanaStats` treats as no measurement.
- **Errors and strictness.** A rejected key and Esc are charged to `errorTarget()`. `handleIntent(intent)` takes no strictness: it is fixed by `loadPrompt`, and a settings change makes the trainer restart the session.
