# ADR 047: Text Stream Trimmed by Whole Lines

- **Status:** In force. Replaces the trim rule of [ADR 040](040-text-stream-window-and-dom-writer.md) (30 tokens kept behind the caret) and of [ADR 043](043-keystroke-latency-gate-and-stepwise-publishing.md) (trim when more than 60 are behind). Item 1 is amended by [ADR 060](060-long-prompt-breaks-between-tokens.md): a prompt wider than the whole line breaks between tokens.
- **Context:** The stream was trimmed by tokens: a prompt left when it ended 30 tokens before the caret. The text that stayed started in the middle of a line, so the browser wrapped it again and every remaining token moved (up to 812 px across and a line down), under the fingers of the user. Because `sync` also worked the scroll out again from zero, the caret and the buffer, which have a transition, glided across the screen for 90 ms. Neither was caught: the e2e tests looked at the text only at the start of a test. Two smaller faults came with it: the red marks of old tokens were dropped on every prompt change, while the tokens were still drawn (so a resize lost them), and the fonts were measured once, by a promise that may already have been resolved.
- **Decision:**
  1. **Whole lines leave.** A line breaks only between prompts (`.nk-word` is `nowrap`) and breaks greedily from its start. So when whole leading lines are removed, the lines that remain are the same, and a prompt appended at the end changes none of them. `trimIndex` (`lib/stream-layout.ts`) gives the first token of the line above the caret, which keeps the line just typed on screen.
  2. **The view reports, the session cuts.** The writer calls `onTrim(token)` when the caret changes line and after each measurement, from the boxes it already has (no layout read on a keystroke). The session stores it (`setTrimPoint`) and uses it in `publishStream`: the stale head is cut only when the window is published, and only when `MIN_TRIM_TOKENS` (60) can leave, so the redraws stay as rare as in ADR 043 (about one in sixty keys). `shouldPublish` takes the window already cut.
  3. **Cap for a view with no layout.** `HARD_BEHIND_TOKENS` (300) bounds the tokens kept behind the caret when no line is reported (no layout, or all the text on one line), so a zen test cannot grow the stream without limit.
  4. **No glide.** `measure()` (so `sync` too) puts the caret and the buffer in place with `.is-placing` on the root, which switches their transition off, and flushes the style before removing the class.
  5. **Marks follow the DOM.** The errored set loses a token only when the window that drew it is replaced, by the head of the new one.
  6. **Fonts.** The writer also measures on `document.fonts` `loadingdone`, and stops listening in `destroy`. A shift from a late font was not reproduced; this is a precaution.
  7. **`reject()`** no longer reads styles: the easing and the media query object are taken once when the writer is made (`matches` stays live).
- **Justification:** Cutting at a line start is the only cut that leaves the layout of the rest unchanged, and the view is the only place that knows where the lines are. The arithmetic runs only when the caret changes line, and the extra cost of a redraw is the same as before.
- **Consequences:** The stream keeps up to about two lines more than before between redraws, and a redraw is a little rarer than the old one. After a resize that changes the number of lines, the next redraw cuts at the line start of the new layout, which may move the text once; a resize is not a keystroke. e2e (`stream.spec.ts`) now types 260 keys in Single Kana and Words, and fails when a kept token changes its place relative to the others at a redraw or when the caret is off its target after one. Tests of the old trim in `session.test.ts` and `stream.test.ts` were changed for this rule (spec `frontend.md`, "Stream").
