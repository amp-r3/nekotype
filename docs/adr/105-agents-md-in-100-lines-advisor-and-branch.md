# ADR 105: AGENTS.md Within 100 Lines; the Branch to Work In; an Advisor Before the Push

- **Context:** Every line of `AGENTS.md` is loaded into each agent session ([ADR 024](024-agents-md-as-the-single-agent-instruction-file.md)). By November 2026 it held 126 lines, about 12 KB: a log of the phases, a list of the packages, the CI and the hooks described in three places, and rules that lint and the hooks already enforce. Its git workflow contradicted itself twice: "commit when `verify:quick` passes" next to "do not run it by hand: the hook does it", and "do not commit to a branch the maintainer did not ask for" next to "push and open a PR without asking". On 2026-11-23 the maintainer asked to cut it to at most 100 lines, to resolve both contradictions and to add how an agent uses an advisor tool, following Anthropic's recommendations.
- **Decision:**
  1. **100 lines.** The pre-commit hook rejects a staged `AGENTS.md` or `CLAUDE.md` over 100 lines instead of 250. `AGENTS.md` keeps what an agent cannot find or infer itself: the FSD boundaries, the purity of the engine and the model, the hot path, the budgets, the data and deployment rules, the licences, the language of communication. A fact that lives in `README.md` or `docs/` is linked, not repeated; a rule that lint, a hook or CI enforces is not restated.
  2. **The hook verifies.** An agent does not run `verify:quick` by hand: the pre-push hook runs it.
  3. **The branch.** An agent works in the current branch. On `main`, or on a branch whose pull request is merged, it creates a branch from `origin/main`. When the task is done it commits, pushes and opens a pull request without asking.
  4. **The advisor.** Where an `advisor` tool is available, an agent calls it after reading the code and before the first edit of a task longer than a few steps, when an error repeats, and before changing the approach; a small edit needs none. Before the push it runs the tests of the change, commits locally, prints `git diff <base>...HEAD` in the session (`<base>` is the pull request's target branch) and calls the advisor as a reviewer; it pushes after fixing what the review found. Advice that contradicts the code or the test output is put back to the advisor with the conflict described, then to the maintainer.
- **Justification:** Shorter instructions leave more of the context to the task, and a rule kept in one place does not drift. The limit holds because the hook enforces it. A review that sees the committed diff before the push catches a mistake while it is cheap. The diff is taken against the pull request's target, not `main`, because the pull requests of a phase can target an integration branch (P7 PRs 8–11 went into `p7-switch`).
- **Rejected alternatives:** Writing 100 in `AGENTS.md` and leaving the hook at 250: nothing would hold the limit. Moving the removed text into `docs/`: every removed fact was already in `README.md`, `docs/spec/` or `docs/architecture/`, except habits the code shows by itself (tests colocated as `*.test.ts(x)`, the style of the surrounding code).
- **Consequences:** `.githooks/pre-commit`, the hook table of `README.md` and the executor instructions of `p7-plan.md` say 100.
- **Status:** In force. Amends [ADR 024](024-agents-md-as-the-single-agent-instruction-file.md): the limit is 100 lines.
