# ADR 089: The Sign-Out Dialog Names Unsent Results or Unsent Progress; Dialog Fields Fill the Width and the Notice Line Sits Beside the Actions

- **Status:** In force. Amends [ADR 079](079-account-and-report-states.md), item 1 (where the notice line of a dialog sits). Item 1 is amended by [ADR 094](094-design-system-without-typing.md): with no results, unsent data is always named by the one progress line.
- **Context:** P5 PR 8 builds sign-out ([p5-plan.md](../archive/p5-plan.md)). The design drew one text for the sign-out dialog, which counts unsent results; but a device can hold unsent learning progress or typing statistics and no results, and that text cannot say so. The maintainer asked for the gap to be drawn in the design artifact first. Reviewing the account previews, the maintainer also found the delete-account dialog inconsistent: its field did not read as a field, the controls had different widths, and an empty band stood above the buttons. The report dialog of PR 12 had the same three faults.
- **Decision:** Design decisions 126 and 127 in [`decisions.md`](../design/source/decisions.md), exported from the design artifact.
  1. **Sign-out text** (126). With unsent results the dialog names their count, with plural forms (`3 results have not been sent yet. If you sign out now, they will be lost.`). With no unsent results but other changes waiting (a `delta` record or a batch without results): `Some progress has not been sent yet. If you sign out now, it will be lost.` / `Часть прогресса ещё не отправлена. Если выйти сейчас, она пропадёт.` Settings do not count: sign-out resets them anyway. Nothing unsent, no dialog.
  2. **Fields in a dialog** (127). `Input`, `Select` and `Textarea` take the full width of the dialog's body and are filled with `bg`: the dialog is `bg-raised`, the fill fields have on the page. The Turnstile slot is the full width too, 65 px high (the widget's `flexible` size).
  3. **The notice line of a dialog with a request** (127) moves from above the actions into the actions row, left of the buttons (`Dialog` `note`), two lines high; below 640 px it takes its own row above them. It stays reserved, so a message never changes the dialog's height.
- **Justification:**
  - _Two texts._ The count is the most concrete thing to name, and results are what a user remembers doing; a generic line for everything would hide a known number. Without results the dialog still has to say that something is lost, or signing out would silently drop learning progress.
  - _`bg` fill in a dialog._ It keeps the field's rule (a filled area, no border) and needs no new token; a border would add a second field style.
  - _The notice beside the actions._ A reserved line above the actions cost an empty band of about 70 px in every dialog that had no message; beside the buttons the same reservation costs nothing on a desktop. The rule that a notice never moves the layout is kept.
- **Consequences:** `Dialog` gains a `note` prop in the reference bundle (`bundle.js`, `bundle.css`, `index.d.ts`); the application's `Dialog` gets it with the first dialog that has a request (PR 11, PR 12). [ADR 079](079-account-and-report-states.md) item 1 ("one reserved `Notice` line above the actions") is replaced by item 3 above. On a 360 px phone the dialog's body is 296 px wide and Cloudflare draws the widget at no less than 300 px; this was true of the fixed size too and is left to PR 12.
