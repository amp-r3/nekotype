# ADR 079: Account, Sign-In and Report Dialog States for P5

- **Context:** The design system drew the account section of `/settings`, the sign-out and delete dialogs and the report dialog for a phrase with its offline state. P5 builds sign-in, sync, account deletion and content reports, and ten states were not drawn (the P5 plan, question Q2, items a–j): the report dialog for a word, while sending, after sending and on failure; what happens to a running test under that dialog; signing in to another account with unsent data; the OAuth failure notice; an expired session outside `/settings`; sign-out and deletion without a connection; deletion in progress and failed; a profile without a name. Three of them are product behaviour, not only appearance. The maintainer chose each of those in the design session of 15 November 2026.
- **Decision:** Design decisions 114–124 in [`decisions.md`](../design/source/decisions.md), exported from the design artifact, with the spec changed in the same pull request.
  1. **Report dialog** (114–116). A word gets the same dialog as a phrase with its own title. While the report is sent the fields and both actions are disabled, `send` reads `sending…` and the dialog cannot be closed; afterwards it holds one line and `close`. Failures show in one reserved `Notice` line above the actions: the check failed, the report was not sent, the check did not load (with `retry`), no connection.
  2. **A running test under the report dialog** (117). Nothing special: keys in a dialog are not input, so a time or count test ends by the idle rule and zen goes on.
  3. **Another account** (118). A dialog on `/` with `cancel` and `discard and continue`; the screen behind it stays in its loading state.
  4. **Sign-in notice** (119). The reserved notice line of `/` shows `sign-in was cancelled` or, in `miss`, `sign-in failed. try again in settings.` until the next navigation, after the load error and the storage notice.
  5. **Expired session in the navigation** (120). The link at the right returns as `sign in again` on every screen and leads to `/settings`.
  6. **Sign-out and deletion need the server** (121). Offline both buttons are disabled with `Needs a connection.` With an expired session sign-out works and deletion is disabled with `Sign in again to delete the account.`
  7. **Deletion in progress and failed** (122), **the profile** (123): the button reads `deleting…` and the dialog cannot be closed; a failure shows in the dialog's notice line; the profile's name line is the display name, else the email, else `account`; no avatar image.
  8. No new token, component, icon or glyph, and no change to the reference bundle (124).
- **Justification:**
  - _A running test._ Ending the test when the dialog opens would lose a test to a stray click; pausing it needs a state the product does not have and rules for KPM and the personal best. The idle rule already covers a user who stopped typing.
  - _`sign in again` in the navigation._ A plain `sign in` reads as signed out and suggests the data is gone; showing nothing leaves sync stopped unnoticed until the user opens `/settings`. The string already exists in the status line. It is a link, not `miss`: the application keeps working locally.
  - _Sign-out needs a connection._ Signing out offline cannot delete the session on the server, so the session and its cookie would outlive the sign-out, a risk on a shared computer. With an expired session there is no session left to delete, so sign-out works and lets a user who lost the provider account clear the device. Deletion needs a valid session in every case.
  - _A dialog that cannot be closed during its request._ Closing would not stop the request, and a failure message would be lost with the dialog. The existing `Dialog` already hides its close button and ignores Esc when no close handler is passed, so the component does not change.
  - _One reserved notice line in a dialog._ The system's rule that a notice never moves the layout, applied to dialogs: the line is always there, so a failure does not change the dialog's height.
  - _Wording._ "verification" instead of the plan's "the check", which made `failed to load the check. check the connection…`; the Russian sign-in failure is shortened so that it stays on one line at 360 px.
