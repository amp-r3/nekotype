# ADR 037: Router and Application Shell

- **Status:** In force. Amended by [ADR 061](061-schema-reset-before-release.md): `/learn` is removed in P3 without a redirect. The rewrite destination of `_redirects` is amended by [ADR 039](039-redirects-rewrite-to-root.md). Amended by [ADR 058](058-learning-first.md) from P3: `/` is the learning screen, the trainer moves to `/type`, `/learn` redirects to `/` with a 301, and `ModePanel` has no rows button.
- **Context:** The P2 acceptance list asks for a dependency-free router with route stubs and `_redirects` entries ([Architecture](../spec/architecture.md), [Frontend](../spec/frontend.md)). The app was one screen: `TrainerPage` drew its own frame, top bar and dialogs, and "Reset progress" lived in the top bar, which the design system replaces by a navigation without it (ADR 031, A33).
- **Decision:**
  - **Router.** A History API router in `shared/lib` with a `currentPath` signal, `navigate()` and a popstate listener. Paths only: no query, hash or parameters. A trailing slash is the same path. Modified clicks stay with the browser.
  - **Routes.** `ROUTE_PATHS` is the one list; `routes` is a `Record` over it, so a missing loader is a type error. `/` is in the initial chunk; the other four are dynamic imports. Loaded screens and failures are signals in `app`; a failed chunk shows a message with a retry, and the retry loads it again.
  - **Shell.** `app/App.tsx` owns the frame, `Nav`, `Footer` and the language switch. `Nav`, `Footer` and `Link` are `shared/ui` views that take labels and the navigation handler as props, as "UI architecture" requires. Pages draw their content only.
  - **Pages.** `learn`, `stats` and `about` are stubs. `settings` is real: it takes "Reset progress" from the old top bar, with the same confirmation dialog. The tagline of the top bar is gone with it. An unknown path in the app shows a not-found screen; on the server, `404.html` answers it.
  - **ModePanel.** `ConfigBar` becomes `ModePanel` (two rows, as in the design) and owns the rows dialog. The rows button is shown for the kana material only, with the number of selected rows; with words or phrases the rows do not apply.
  - **`_redirects`.** Four rules, status 200, no catch-all: a catch-all would turn a missing `/assets/*` file into `index.html` cached as immutable, the failure `404.html` exists to prevent. A test compares the file with `ROUTE_PATHS`.
  - **Prefetch.** After the first render, on `requestIdleCallback` (a 1.5 s timer in Safari), every lazy screen and the content chunks load. Failures are ignored; the screen reports its own failure when it is opened. Content: the selected vocabulary, or both kinds while kana are selected. Chunks are not split by script yet, so there is nothing finer to match; P4 revisits it.
  - **Tab title.** `document.title` follows the screen and the language.
- **Justification:** A router of about 50 lines covers five fixed paths; a library would add more to the initial chunk than the budget leaves. A route record keyed by the path list keeps the redirects, the table and the navigation from drifting. Prefetching on idle keeps the application usable when the connection drops, which the spec asks for, without touching first load. Alternatives rejected: `preact/compat` `lazy` and Suspense (adds the compat layer to the initial chunk); a hash router (breaks the address format the redirects and the 404 handling assume); a catch-all redirect (see above); keeping "Reset progress" in the navigation (the design and A33 put it in settings).
