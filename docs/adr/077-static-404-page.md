# ADR 077: The Static 404 Page Mirrors the App's Not-Found Screen

- **Status:** In force. Amends [ADR 037](037-router-and-application-shell.md) and [ADR 039](039-redirects-rewrite-to-root.md) only in what `404.html` looks like; the routing they define is unchanged.
- **Context:** An unknown path has two answers. Locally the dev server falls back to `index.html` and the app draws its own not-found screen (neutral cat, `go home`, the navigation). On Cloudflare Pages there is no catch-all rule, so the path is answered with the static `public/404.html` and a real 404. Design work on the not-found screen (#130) touched only the app's component, and production kept the P2 page (a dark page with `かな`, English and Russian in one paragraph). Nothing compared the two.
- **Decision:**
  1. `404.html` stays a static file, so the status stays 404 and a missing `/assets/*` file is never answered with the application. It is redrawn as the app's not-found screen: the same dark tokens, the neutral cat as inline SVG, the same title and line, and a primary `go home` link with the `enter` hint. It has no navigation, because the application does not run there.
  2. It is bilingual: both strings are in the markup, and a short inline script picks `nekotype:locale` or the browser language (the rule of `detectLocale`), sets `lang` and the visible strings, and sends `Enter` to `/`. Without scripts the page is in English.
  3. The page makes no other request: inline styles, inline SVG, system fonts.
  4. A test (`not-found-page.test.ts`) keeps it equal to the sources: the strings of `en` and `ru`, the cat's shapes in `cat.tsx`, the dark colours in `tokens.css`, no external references, at most 5 KB gzip. The deployment smoke test requires the `data-page="not-found"` marker on every 404 it checks.
- **Justification:** The file is small and changes rarely; a test that fails when the sources move is cheaper than a build step. Alternatives rejected: generating the file at build time from the app's components (a second render path in the build for one page); a catch-all rewrite to the SPA (the failure ADR 037 and 039 exist to prevent); linking the app's CSS and fonts (hashed names change with every build and one more request on a failed one).
