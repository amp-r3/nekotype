# ADR 091: The Sync e2e Run Against `wrangler pages dev` With a Fake OAuth Provider That Lives Only in the Test Folder

- **Context:** P5 PR 9 ([p5-plan.md](../archive/p5-plan.md), D9, S12) adds the browser tests of sync: a guest signs in, a test finished offline arrives, two tabs finish work together. They need the real API, a D1 database and a sign-in that does not leave the machine. The existing e2e configuration serves the bundle with `vite preview`, which has no Functions.
- **Decision:**
  1. **A second configuration.** `apps/web/playwright.sync.config.ts` runs `e2e/sync/*.spec.ts` on Chromium with one worker. Its web server is `e2e/sync-server/start.mjs`: it builds `dist-e2e-sync`, applies the migrations to a local D1 in a fresh temporary directory (`--persist-to`) and starts `wrangler pages dev` on port 5274 from `e2e/sync-server/`, where `wrangler.toml` sets `ENVIRONMENT = "test"`, `APP_ORIGIN = "http://localhost:5274"` and `SYNC_MIN_INTERVAL_MS = "0"`. The first configuration ignores `e2e/sync/`. `pnpm run e2e` runs both; `pnpm run e2e:sync` runs the second alone.
  2. **The fake provider.** `e2e/sync-server/functions/api/[[route]].ts` calls the real `createApp` with an `OAuthProviders` whose `authorizationUrl` points at `/api/test/authorize`, a route that only this entry answers: it reads the cookie `e2e_user` and redirects to the real callback with its value as the code; `profile` turns the code into a verified `<code>@example.test`. The real callback, session and user code run. A test sets the cookie and presses the real button. Every test uses a user name of its own, because the database lives for the whole run.
  3. **Why it is not a backdoor.** The fake provider and the test route are in `apps/web/e2e/`; the deployed bundle is built from the root `functions/` only, and `apps/api/src` has no test-only branch. The test of the deployed bundle (`apps/api/src/entry.test.ts`) fails when a deployed file imports the web app or contains `api/test`. The entry is type-checked by `apps/api` (its `tsconfig.json` includes the folder).
  4. **`package.json` in `e2e/sync-server/`.** `wrangler pages dev` looks for `wrangler.toml` from the nearest `package.json`, not from the working directory; without one it read the repository's `wrangler.toml` and `.dev.vars`. The file makes the folder the root of its own Pages project; it is not a workspace member (`pnpm-workspace.yaml` lists `apps/*` and `packages/*`). The server starts the binary `node_modules/.bin/wrangler` directly: `pnpm exec` from that folder runs in the workspace root.
  5. **Time.** The client sends at most one request per 10 seconds; tests that would wait for it install Playwright's clock (`page.clock.install()`) before the first navigation and jump with `fastForward(10_000)`. Time flows normally between jumps.
  6. **Scope.** Turnstile and the report dialog are not part of any e2e (the widget needs Cloudflare's network). Two devices are covered below the browser (ADR 052): a second browser context signs in as the same account to see what arrived. The history of a new device is filled on demand from `GET /api/results` (PR 10), so until then these tests read the counters and the personal bests, which come with the snapshot.
- **Justification:**
  - _The real code runs._ Only the provider is replaced, so a mistake in the callback, the session cookie, `/api/me` or the sync handler fails these tests.
  - _A test folder, not a flag._ A switch inside `apps/api/src` would ship with the bundle; a file outside it cannot.
- **Rejected alternatives:**
  - _`vite preview` with a proxy to a separate wrangler process_ would put two servers and a port handshake in front of every run.
  - _Mocking `/api/*` with `page.route`_ would test the client against our own assumptions about the server.
- **Consequences:** `quality.md` (S12), `README.md` and `AGENTS.md` name the command; `docs/architecture/quality-gates.md` lists the second configuration. The suite adds one more production build to CI; its duration is in the pull request.
- **Status:** In force.
